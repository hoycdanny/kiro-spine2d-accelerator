# デモ — 2 分、9 ステップ

[English](README.md) · [繁體中文](README_ZH.md) · [简体中文](README_CN.md) · [한국어](README_KR.md)

自分で解説しながら進むスクリプトです。実際の MCP サーバーを stdio 経由で動かします。
顧客の前でそのまま実行できます。Spine の **trial** だけで完走し、書き込みは `demo/out/` のみ、
実行ごとにそのフォルダをリセットします。

## 実行

```bash
npm install
npm run build
npm run demo
```

任意の依存を 2 つ入れるとデモが完全になります。無くても動作し、何をスキップしたか明示します。

```bash
uv sync --project python          # ステップ 2、PSD の部分
npx playwright install chromium   # ステップ 5〜7、ビジュアルの部分
```

ウォーム状態で約 5 秒です。終わったらこの 2 つのフォルダを開いてください。これがデモの中心です。

```
demo/out/generated/images/  アタッチメントごとの個別 PNG — File -> Import Data はこれを参照します
demo/out/preview/           アニメーションのレンダリング 4 フレーム
demo/out/regression-diff/   atlas の 3 ピクセルずれを捕まえた差分画像
```

## 各ステップで話すこと

| ステップ | 画面に出るもの | そのまま言える一言 |
|---|---|---|
| 1. 環境確認 | trial を検出、7 つの操作がブロック、Python サイドカー準備完了 | 「時間を無駄にする前に、できないことを先に伝えてくれます。」 |
| 2. PSD → リグ | ボーン 12、アタッチメント 6、仮想ボーン 6、`cape` はスキップ、さらに個別 PNG 6 枚を入れた `generated/images/` フォルダ | 「素材を入れてリグが出る。しかも Spine エディタを一度も開いていません。だからこの部分は trial でも動きます。JSON の隣にある `images/` フォルダが `File -> Import Data` を成立させている本体です。エディタは atlas ではなくこの個別画像に対してアタッチメントを解決します。」 |
| 3. 検査 + lint | atlas の相互チェック通過、修正方法付きの警告 2 件 | 「価値があるのは相互チェックです。スケルトンが必要としているのに atlas に無い領域は、ランタイムで『何も』描かれず、どこにもエラーが出ません。」 |
| 4. アニメーターが動きを追加 | `+ animations: idle, wave` | 「エクスポート JSON のテキスト差分は読めません。これはレビュアーが本当に聞きたいことに答えます。」 |
| 5. レンダリング | 240×240 で 4 フレーム、ピクセル被覆率を報告 | 「本物の Spine web ランタイムでヘッドレスに描画します。被覆率があるので『静かに何も描かれなかった』を検出できます。」 |
| 6. ベースライン + 照合 | 4/4 フレームが許容範囲内 | 「これが、変更ごとにパイプラインが通すゲートです。」 |
| 7. わざと壊す | 4/4 フレームが FAIL、ピクセル数と差分画像付き | 「atlas の領域を 3 ピクセル動かしました。スケルトンデータは一切変わっていません。ビジュアル検査だけが捕まえられます。」 |
| 8. Unity スキャフォールド | `hero.atlas → hero.atlas.txt`、mix テーブル、コントローラー | 「spine-unity は素の `.atlas` を読み込めません。このルールは誰かの記憶ではなくツールに入っています。」 |
| 9. ライセンス境界 | `CAPABILITY_DENIED` と実行予定だったコマンドライン | 「trial では拒否します。そして実行しようとしたコマンドを返すので、購入後にそのまま再実行できます。」 |

## ライブで見せる場合

Power を Kiro に入れていれば、次のプロンプトで同じ道筋を会話で再現できます。
先に `npm run demo` を一度実行して `demo/out/` にファイルを用意しておくとスムーズです。

```
いまのマシンの Spine 環境で何ができますか？

demo/out/hero.psd を Spine のリグにして demo/out/generated に出力してください。

demo/out/generated/hero.json を atlas と一緒に監査して、問題を教えてください。

wave アニメーションのフレームを 4 枚レンダリングして保存してください。

ビジュアルのベースラインを作って、それと照合してください。

この資産を Unity プロジェクトで使うには何が必要ですか？
```

最後の 1 つは締めに向いています。必要なファイル名変更、対応するランタイムブランチ、そして
このスケルトン自身のアニメーションから導いた mix テーブル付きのコントローラーを返します。

## 正直に先に言っておくこと

- **サンプル素材は色の四角形**で、`make-sample-psd.py` が生成します。見せているのはリグの規則
  （関節のピボット、仮想ボーン、描画順）であり、絵の品質ではありません。
- **export、pack、import には購入ライセンスが必要です。** ステップ 9 はその境界を意図的に見せます。
  デモの他の部分は trial で動きます。
- **レンダリングは Spine web ランタイム**によるもので、Spine 自身の画像エクスポートではありません。
  Spine のエクスポートが正式なビジュアル出力で、こちらはデスクトップ環境なしにパイプラインが
  自己検証するために存在します。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `dist/server.js is missing` | `npm run build` |
| ステップ 2 で uv が使えないと出る | `uv sync --project python`、またはそのまま内蔵の小さなリグで続行 |
| ステップ 5〜7 がスキップされる | `npx playwright install chromium` |
| Spine エディタで `File -> Import Data` した後、キャンバスが真っ白 | エディタは読み込んだ JSON を基準に各アタッチメントを `<skeleton.images>/<attachmentName>.png` として解決し、`.atlas` は一切読みません。`demo/out/generated/images/` が `hero.json` の隣にあり、アタッチメントごとに PNG が揃っているか確認してください。フォルダが無ければ `emitLooseImages` true（既定値）で再実行します |
| どこかで `CLI_TIMEOUT` が出る | Spine エディタのウィンドウをすべて閉じる。ランチャーは開いているエディタに CLI 要求を渡し、戻ってこなくなります |
| テキストの記録が欲しい | `NO_COLOR=1 npm run demo > demo-transcript.txt` |
